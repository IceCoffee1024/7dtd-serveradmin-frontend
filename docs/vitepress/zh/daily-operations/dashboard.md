# 仪表盘

> 面向已登录的管理员和轮值运维人员。需要可达的后端以及读取游戏服务器统计和系统指标的权限。数据为空或停留在旧时间时，通过[故障排查](../reference/troubleshooting)排查。

## 目的

仪表盘是值班入口：快速判断服务器是否在线、采样是否新鲜、资源是否异常，并跳转到最短调查路径。它不是逐帧性能分析器，也不替代审计或游戏事件日志。

## 开始前

- 使用有状态和系统指标读取权限的账号登录。
- 确认后端和游戏进程正在运行，并准备[控制台与日志](./console-and-logs)用于交叉核对。
- 将页面显示时间视为采样时间，不把它当作实时帧的证明。

## 主要区域

- **状态与概览**：在线/离线、在线玩家与上限、FPS、服务器版本/区域/语言和游戏时间摘要。
- **资源监控**：常驻内存、堆、CPU/RAM/网络等系统采样，以及区块、实体、物品、僵尸和动物数量。
- **新鲜度**：系统指标采样时间、运行时长和下一次计划重启（若已配置）。连续刷新时，时间和数值应变化；空值应保持为未知，而不是被当作零。
- **最近活动**：最近玩家进入/离开等事件摘要，供进一步打开玩家、游戏事件或聊天页面。
- **快速操作**：页面提供的刷新、重启或其他入口。重启按钮属于破坏连接的维护操作，必须在窗口内使用。

## 操作步骤

1. 登录后先看在线/离线状态和采样时间；若状态为离线，确认后端和游戏进程，而不是立即重复点击重启。
2. 对照 FPS、内存、堆、区块和实体趋势，记录异常开始时间。只看一个卡片不足以判断原因。
3. 从最近活动打开对应玩家或日志页面，使用玩家 ID、时间范围和事件类型缩小范围。
4. 需要维护时先确认公告、备份和权限，再使用快速操作；完成后回到仪表盘等待采样恢复。

## 验证结果

- 连续两个刷新周期能看到采样时间或指标更新；在线玩家数量与玩家列表大致一致。
- 后端短暂不可达时页面显示明确错误/空状态，恢复后刷新能回到真实值。
- 重启后状态从离线回到在线，FPS/内存卡片重新出现；对应重启或错误记录可在[控制台与日志](./console-and-logs)查到。

## 限制与安全说明

::: warning
仪表盘指标是后端定时采样，可能有延迟；用控制台和游戏日志确认关键事故。浏览器按本地时区格式化部分时间，计划任务时区以 Scheduler/Backup 设置为准。
:::

::: danger
重启会断开玩家；不要把“刷新”误当作“重启”，也不要在多个管理员同时操作时重复执行。
:::
