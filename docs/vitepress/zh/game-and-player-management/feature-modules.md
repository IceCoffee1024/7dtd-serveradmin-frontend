# 功能模块

> 面向可以查看模块元数据和配置的已登录管理员。需要后端可达；修改模块还需要对应功能的管理权限，部分权限会要求游戏已就绪。

## 目的

在模块中心确认游戏和运维功能是否启用、配置是否健康、运行时正在做什么，以及哪些依赖可能导致路由或命令不可用。

## 开始前

- 使用能够查看功能模块定义、并在需要时修改设置的账号登录。
- 确认后端和游戏进程可达。权限和命令可能标注需要认证、游戏就绪、管理员或在线玩家。
- 修改线上模块前准备好对应功能的设置页面、回滚值和维护窗口。

## 操作步骤

### 启用与停用

1. 打开 **功能模块** 并刷新模块列表。按已启用、已禁用、有问题或不可用筛选，再打开模块查看 key、健康状态、启用开关、配置状态和最近检查时间。
2. 要启用或禁用功能时，打开它关联的设置路由，修改开关和必填字段并保存。回到模块中心刷新，直到启用状态和配置状态与保存值一致。

### 配置健康

3. 在模块详情抽屉阅读 **配置** 和 **健康问题**，不要只依据绿色状态判断可用。到关联设置页面修复无效值、缺失设置或过期检查，再次刷新或执行可用操作。

### 运行时状态

4. 在详情抽屉打开 **运行时状态**。按 runtime、history、cooldown、reward、request、cache 或 first-join 等类别筛选，检查更新时间和值。只有确认范围安全时，才对明确的 scope 执行清理。

### 依赖警告

5. 查看 **依赖**、**路由**、**命令** 和 **权限**。标记为已禁用或不可用的依赖会解释子路由、命令或能力为何不可用；先修复依赖，再重新检查依赖它的模块。

## 验证结果

- 模块行显示预期的启用状态、健康的配置状态和较新的检查时间。
- 运行时状态显示当前记录或成功的空状态；清理结果报告了请求范围和数量。
- 计划使用的工作流不再显示未解决的依赖警告，关联路由和命令可见且状态正常。

## 限制与安全说明

::: warning
模块健康是后端某一时刻的检查，不代表每个游戏钩子都正在产生事件。依赖禁用或不可用会让路由看起来为空；运行时值和时间戳只用于诊断，关键事故还要与审计或游戏事件日志交叉核对。
:::

::: danger
禁用模块通常会停止新的采集或命令注册，但不会自动删除已存数据。清理和重置可能删除状态；执行前确认 scope、保留结果，并在维护窗口内变更。
:::
