# 传送

> 面向有传送管理权限的已登录管理员。需要启用传送模块和所选子模块；实时工具要求游戏已就绪，目标要求在线。

## 目的

通过直接工具、可配置的家/城市/好友/返回服务以及可检索的传送历史，运维和审计玩家移动。

## 开始前

- 在[功能模块](./feature-modules)检查模块和子模块健康状态，再核对目标的稳定 Player ID 或当前在线 Entity ID。
- 移动玩家前确认目的地坐标、货币费用、血月策略、各子模块冷却和可选的全局冷却。
- 强制移动要在维护或事故窗口内执行，并保留产生的日志行。

## 操作步骤

### 工具 {#tools}

1. 在 **工具** 刷新在线玩家，选择 **传送到坐标** 或 **传送到玩家**，填写坐标或源/目标玩家，提交前阅读确认对话框。

### 设置 {#settings}

2. 在 **设置** 只启用需要的子模块，并设置家/城市/好友/返回的权限、费用、请求过期、家数量、血月规则、命令名和冷却。如果启用全局冷却，要把它当作所有传送类型共享的池。

### 城市 {#cities}

3. 在 **城市** 新增或编辑带名称的目的地，填写坐标、朝向、可选货币费用、启用状态和排序。线上活动中修改前先禁用目的地；删除前确认没有玩家命令依赖它。

### 家园 {#homes}

4. 在 **家园** 按稳定 Player ID 搜索，检查家名称、坐标、所有者和创建时间；删除前确认玩家并阅读删除确认。

### 日志 {#logs}

5. 在 **日志** 按 Player ID 和 UTC 时间范围筛选，将时间、Home/City/Friend/Back 子系统、起止坐标、支付费用、备注和关联玩家画像与事故时间线对照。

## 验证结果

- 成功的工具操作报告成功，目标下一次位置或玩家视角与请求目的地一致。
- 设置重新加载后显示预期的启用标志、限制、费用和冷却；被拒绝的请求明确显示权限、冷却、余额或血月原因。
- 日志行包含玩家、子系统、起止坐标、费用、结果/备注和 UTC 时间。

## 限制与安全说明

::: warning
传送具有破坏性，坐标错误可能让玩家卡在危险地形。能打开页面不代表绕过子模块、游戏就绪、在线玩家、货币或冷却检查；Entity ID 只在当前会话稳定，重连后必须重新确认。
:::

::: danger
强制传送和删除家位置都会改变玩家状态。二次确认目标和坐标，避免在战斗或不可逆事件期间移动玩家，并保留日志/审计证据。不要向事故团队外共享私有家位置坐标。
:::
