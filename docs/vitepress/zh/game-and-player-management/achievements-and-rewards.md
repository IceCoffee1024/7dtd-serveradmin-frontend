# 成就与奖励

> 面向有成就以及经济/奖励管理权限的已登录管理员。需要启用成就模块；经济、游戏物品和命令依赖只在配置对应奖励类型时才需要。

## 目的

定义可度量的里程碑、复核获得成就的玩家，并在不重复或误发价值的情况下配置在线时长奖励。

## 开始前

- 在[功能模块](./feature-modules)检查模块健康和依赖警告。
- 编辑定义前确定触发类型、阈值、服务器预期的一次性/重复行为，以及准确的奖励和消息载荷。
- 尽可能用一次性测试玩家测试物品、经济和受限控制台命令载荷。

## 操作步骤

### 成就定义 {#achievement-definitions}

1. 在 **成就定义** 新增或编辑名称、描述、触发类型（`Level`、`ZombieKills`、`PlayerKills`、`Deaths` 或 `GameStage`）、阈值、排序、启用状态、货币数量、玩家/广播消息和受限控制台命令。
2. 保存定义，重新加载列表，确认持久化 ID、触发器、阈值、启用标志和奖励字段。活动进行中要调整阈值时先禁用定义。

### 成就记录 {#achievement-records}

3. 在 **成就记录** 按成就或 Player ID/名称筛选，检查获得时间、奖励金额和玩家身份。只有有记录的修正理由才删除/重置记录；条件再次满足时可能重新发放。

### 成就设置 {#achievement-settings}

4. 在 **成就设置** 启用或禁用处理并保存。在 **在线奖励** 设置启用状态、周期、金额、未满周期策略和玩家消息；保存后重新加载两个页面。

### 在线奖励 {#online-rewards}

5. 用测试玩家执行一次受控触发或在线周期，将玩家消息、经济流水/物品交付/命令结果、成就记录和模块运行时状态对照，确认无误后再面向全体启用策略。

## 验证结果

- 定义和设置页面重新加载后显示预期的持久化值，且没有依赖警告。
- 受控触发创建恰好一条预期记录并有匹配的奖励证据；在线周期使用配置金额和消息且没有意外重复。
- 失败奖励以错误或缺失结果形式可见，必须调查，不得默认为成功。

## 限制与安全说明

::: warning
定义和记录是两类数据：删除定义可能删除获得历史，删除获得记录可能允许以后重新发放。货币和命令奖励依赖其他模块及服务器权限；定义启用不等于奖励已成功交付。
:::

::: danger
成就阈值、在线奖励和控制台命令可能产生大量或重复发放。使用最小权限、保守测试值，并在允许的命令/`allowUnsafe` 策略下执行，保留流水和审计证据。
:::
