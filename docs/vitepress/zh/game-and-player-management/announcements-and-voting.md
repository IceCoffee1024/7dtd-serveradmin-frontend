# 公告与投票

> 面向管理面向玩家的公告和投票策略的已登录管理员。需要后端可达；实时广播/投票要求游戏就绪，并需要游戏公告、投票重启或投票踢出模块权限。

## 目的

发布可预测的游戏内公告，并用明确的阈值、冷却、消息和安全边界配置社区投票。

## 开始前

- 在[功能模块](./feature-modules)确认所选模块已启用且配置健康。
- 修改线上消息或投票规则前检查服务器状态、活动投票、重启窗口、在线人数和管理策略。
- 消息中不要放秘密；条件允许时先用非生产账号测试占位符。

## 操作步骤

### 游戏公告 {#game-notices}

1. 在 **游戏公告** 编辑启用开关、欢迎消息、轮播消息列表和间隔、血月公告。保存并重新加载，再执行安全测试或等待下一次事件确认发送。

### 投票重启 {#vote-restart}

2. 在 **投票重启** 设置最少票数/比例、投票时长、全局冷却、命令文本、成功/失败/冷却消息和重启警告。确认通过投票后会使用预期的维护流程，再保存。

### 投票踢出 {#vote-kick}

3. 在 **投票踢出** 设置投票阈值/时长、目标保护、全局冷却、原因和玩家消息。允许投票前确认目标选择和权限策略。
4. 从游戏聊天或服务器事件日志观察一次受控投票，记录发起人和参与者、最终票数/结果、冷却，以及是否触发重启或踢出，再关闭事故。
5. 要回滚策略，关闭受影响的模块或投票开关，保存并重新加载。这样只会阻止新的公告或投票；已通过的投票要单独调查，不能假设改设置会撤销重启或踢出。

## 验证结果

- 保存后重新加载，启用状态、消息列表、间隔、阈值和冷却均为预期值。
- 测试公告出现在目标玩家可见范围内，受控投票在聊天/日志中报告当前计数和最终结果。
- 通过的重启或踢出有对应的重启/管理/审计证据；失败或处于冷却的投票留下清晰原因且没有执行动作。

## 限制与安全说明

::: warning
公告可能全服发送，投票会影响所有在线玩家。保持占位符有效，按 UTC 规划维护时间，并记住投票配置不保证依赖不可用时游戏一定能执行重启或踢出。
:::

::: danger
通过重启会断开玩家，通过踢出会移除玩家。使用保守阈值和冷却，提前公告破坏性动作，不要用投票设置绕过管理员权限或管理策略。
:::
