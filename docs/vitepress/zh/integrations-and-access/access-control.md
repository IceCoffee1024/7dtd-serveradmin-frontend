# 访问控制

> 面向管理玩家封禁、白名单、禁言、管理员账号和命令权限规则的管理员。这些变更会影响线上玩家，需要对应的游戏服务器权限。

## 目的 {#purpose}

只应用任务所需的最小访问规则，用专用测试账号验证，并保留足够上下文以便安全撤销。封禁和白名单影响玩家登录/准入，禁言只影响聊天，权限影响管理员和控制台命令授权。

## 开始前 {#before-you-begin}

- 从可信的玩家记录确认目标玩家 ID。在工单和截图中使用 `<PLAYER_ID>` 等脱敏占位符。
- 明确这是临时限制、永久限制、白名单、禁言、管理员授权还是命令规则。
- 在修改线上规则前记录原因、操作者、到期时间和审批信息。
- 修改唯一管理员账号或恢复所需命令时，安排第二位管理员共同复核。

## 操作步骤 {#procedure}

### 封禁与白名单 {#ban-and-whitelist}

1. 打开 **封禁与白名单**。页面包含 **封禁**、**白名单** 和 **禁言** 标签，按目标范围选择对应标签。
2. 按玩家 ID 或显示名称搜索。**封禁**包含玩家 ID、显示名称、到期时间和原因；**白名单**只有玩家 ID 和显示名称；**禁言**包含玩家 ID、显示名称、禁言到期时间和禁言原因。
3. 保存条目并等待命令结果。编辑封禁或白名单时，页面会先移除旧规则再写入新规则；禁言编辑使用 `AddOrUpdateMute` 操作，不采用先删除再创建的顺序。离开页面前必须确认结果。
4. 单条删除使用行操作；批量删除先选择行，再在确认对话框中复核选择范围。破坏性操作确认前再次检查列表。
5. 当前授权器会先检查活动的平台封禁或跨平台封禁，再在仅白名单准入模式中检查白名单；白名单或管理员条目不能绕过活动封禁。不要把这个顺序直接推广到其他服务器版本或集成，在受控窗口用同时命中两条规则的专用测试账号验证，并记录目标服务器实际的登录评估顺序。

### 权限 {#permissions}

1. 打开 **权限**，选择 **管理员用户** 为玩家授予管理员权限级别，或选择 **命令权限** 设置控制台命令所需的最低级别。
2. 管理员条目填写 SteamID64，或以 `Steam_`、`EOS_` 开头的 ID，再填写显示名称和 `0` 到 `2000` 的权限级别。在 7DTD 权限模型中，`0` 是最高权限，数值越大权限越低；选择审批的级别并用测试账号验证。
3. 命令规则填写命令名称和所需权限级别。即使当前表单把描述当作运维备注，也应把用途写入变更记录。
4. 保存并重新加载表格，用专用测试账号验证生效规则。不要用唯一恢复账号测试新的管理员级别。
5. 撤销规则时删除选中的条目，或替换为已审批的级别；随后验证之前允许或拒绝的命令已产生预期结果。

## 验证结果 {#verify-result}

- 白名单行只显示预期玩家 ID 和显示名称；封禁显示到期时间和原因；禁言显示禁言到期时间和原因。
- 专用测试账号在封禁和白名单场景得到预期的登录/准入结果，在禁言场景得到预期的聊天结果；同时验证相邻反例并记录封禁与白名单的实际顺序。
- 管理员或命令权限表刷新后显示预期级别，用允许和拒绝命令测试证明规则确实影响命令授权，并确认操作出现在可用审计日志或游戏命令历史中。
- 删除条目后预期恢复路径可用；不要仅凭浏览器中的旧行判断成功。

## 限制与安全说明 {#limits-and-safety}

::: warning
权限级别的顺序由游戏服务器策略决定，不是通用的角色名称。在 7DTD 中，`0` 是最高权限，数值越大权限越低。先用测试账号确认有效级别，不要授予超过任务需要的访问范围。
:::

::: danger
封禁、禁言、批量删除和管理员变更都会立即改变线上状态。错误的玩家 ID 会影响错误对象，移除唯一管理员还可能导致无法恢复；执行前必须确认并保留原规则。
:::

- 白名单或封禁记录不是身份认证系统。请从可信记录确认玩家 ID，并按个人数据保护要求保存导出列表。
