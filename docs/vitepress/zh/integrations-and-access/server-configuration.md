# 服务器配置

> 面向有读取和更新游戏服务器设置权限的管理员。后端必须连接到目标 7DTD 进程；设置保存成功后，部分配置仍需重启才能生效。

## 目的 {#purpose}

查看运行中游戏服务器暴露的配置，并一次只修改一个设置，配合可记录的验证步骤完成变更。

## 开始前 {#before-you-begin}

- 确认当前账号可以读取和更新服务器配置，且当前选中的服务器就是目标服务器。
- 修改网络、认证、文件位置或管理界面设置前，先完成配置备份。
- 约定维护窗口。端口、密码、Telnet、仪表盘和文件位置变更可能导致玩家断线或服务器不可达。
- 在工单和截图中使用 `<SERVER_CONFIG_FILE>`、`<7DTD_SERVER_ROOT>` 等占位符。不要把真实密码或私有路径复制到手册或截图中。

## 操作步骤 {#procedure}

### 查看当前值 {#review-values}

1. 打开 **服务器配置**，等待分组列表加载。服务器、网络、槽位、管理界面、文件和目录位置等分组由后端返回的配置动态生成。
2. 先阅读配置项旁的说明。表格中的值是当前服务器值，不是浏览器中的未保存草稿。
3. 对计划中的变更记录配置键、原值、原因、操作者和维护窗口。

### 编辑并保存 {#edit-and-save}

1. 选择单个配置项的编辑操作，输入新值并确认。值必须符合 7DTD 接受的格式，例如布尔值、端口号、语言代码或目录路径。
2. 等待保存结果并让页面重新读取数据。请求失败时保留原值，先处理校验或连接问题再重试。
3. 多个值有关联时，先保存并验证第一个，再修改下一个，便于将后续回归归因到单项变更。

### 应用线上变更 {#apply-change}

1. 根据 7DTD 对该设置的说明判断是否必须重启。API 接受设置不代表运行中的进程已经重新加载。
2. 发布断线通知，获得批准后执行重启流程，并在新状态验证完成前保留变更前的配置备份。
3. 如果变更影响仪表盘或 Telnet 端点，要同时更新反向代理、防火墙和运维连接信息。

## 验证结果 {#verify-result}

- 刷新 **服务器配置**，确认配置项显示保存后的值，并且仍位于预期分组。
- 需要重启的设置验证游戏进程重新上线、仪表盘仍能认证，并由测试玩家完成连接。
- 网络或访问设置变更要从运维人员使用的同一网络边界测试，并确认存在对应审计记录。
- 重启后新值没有生效时，对照 `<SERVER_CONFIG_FILE>` 中的活动配置；必要时先恢复已知可用值再升级处理。

## 限制与安全说明 {#limits-and-safety}

::: warning
此页面修改的是后端暴露的配置文件或设置，不会验证所有游戏特定的组合关系。请遵循对应 7DTD 版本的配置规则，并保留已知可用备份。
:::

::: danger
修改 `ServerPassword`、端口、Telnet 凭据、仪表盘端点或文件位置可能导致玩家或管理员失去访问。执行前让第二位运维人员复核目标，公开示例不得出现真实主机、凭据或私有路径。
:::
