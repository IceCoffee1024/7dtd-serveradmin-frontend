# 服务器重启

> 面向有重启功能配置、手动执行和历史读取权限的管理员。需要后端已发布并可访问游戏进程；启用计划后，后端才会注册 Cron 任务。

## 目的

配置可预告、可追踪的计划重启，或在维护窗口内手动发起一次重启，并用执行历史和审计记录确认结果。

## 开始前

- 确认当前账号有更新重启设置、执行重启和读取执行历史的权限。
- 先确认维护窗口、在线玩家通知内容、备份和回滚方案。重启会断开在线玩家。
- 为计划填写明确的 `Cron 表达式` 和 `TimeZoneId`。留空时区会回退到服务器本地时区，不要靠浏览器显示时间猜测计划时区。

```text
Cron: 0 6 * * *
TimeZoneId: Asia/Shanghai
```

## 操作步骤

### 设置 {#settings}

1. 打开重启的设置页，先决定是否启用计划重启。关闭时不会注册计划任务，手动执行入口仍需按权限使用。
2. 填写 `Cron 表达式` 和显式的 `TimeZoneId`（例如 `UTC` 或 `Asia/Shanghai`），保存后等待设置重新加载。计划的权威配置是已保存的这两个值。
3. 设置 `预警提前秒数`、`预警消息` 和可选的多阶段预警。消息可使用 `{minutes}`；多阶段消息还可使用 `{seconds}`。多阶段列表有内容时会取代单次预警。
4. 按维护策略选择 `重启前保存世界`、`Graceful` 或 `Force`。只有在明确知道外部启动器需要什么时才填写 `自定义重启命令`；填写后会跳过内置重启流程。
5. 如需避开血月，启用血月窗口延期，并设置黄昏前保护小时数和每次延期分钟数。保存后确认页面提示成功，并再次读取设置确认值没有被回退。

### 立即执行 {#run-now}

1. 进入手动重启页，填写可审计的原因；仅在本次确有需要时覆盖预警秒数或重启模式，留空表示使用设置中的默认值。
2. 在确认对话框中再次确认在线玩家会断线、目标服务器和维护窗口，然后点击立即重启。取消确认不会创建执行记录。
3. 读取页面返回的状态、摘要、耗时和错误信息。倒计时阶段可在设置页点击取消待执行的重启；没有待执行倒计时时取消操作不会产生改变。
4. 等待游戏进程按预期退出并重新上线。不要把“请求已发送”当作服务器已经恢复的证明。

### 历史记录 {#history}

1. 在历史中按 `TriggerSource`（`Cron` 或 `Manual`）、成功状态和时间范围筛选，定位本次运行。
2. 打开详情，核对 `Status`（`Success`、`Failed` 或 `Skipped`）、`Summary`、`ErrorMessage`、开始/结束时间、耗时、操作者和来源 IP。
3. 将历史记录与审计日志、游戏进程日志和重新连接结果对照。计划重启被血月窗口延期、重复请求被跳过或倒计时被取消时，应以历史状态和详情为准。

## 验证结果

- 设置重新加载后，启用状态、Cron、时区和预警值与刚保存的值一致；页面或 API 显示的 `NextRunAt` 只是按当前活动任务计算出的时间点。
- 手动执行产生一条 `Manual` 历史记录，且详情中的摘要/错误与页面返回值一致；服务器重启后能重新连接并且游戏日志没有启动异常。
- 计划执行产生一条 `Cron` 记录。将 `NextRunAt` 当作显示提示即可，真正决定触发时刻的是后端保存的 `CronExpression` 加 `TimeZoneId`（时区为空时是服务器本地时区）。

## 限制与安全说明

::: warning
重启配置依赖后端 Cron 进程和游戏进程状态。`Graceful` 会等待优雅关闭，`Force` 可能丢失尚未写入的数据；`saveworld` 只在配置启用且游戏已启动时执行。预警消息是通知，不是锁定玩家操作的机制。
:::

::: danger
立即重启、强制重启和自定义重启命令都会改变线上状态。执行前必须确认目标、维护窗口、备份和回滚负责人；不要在公开示例中填写真实主机、路径、玩家标识或令牌。
:::

- 历史保留天数会触发自动清理；需要长期留存时请导出审计证据，不要只依赖页面当前列表。
