# 产品概览与生命周期

> 面向服务器所有者、管理员和轮值运维人员。正常部署只需要一个 GitHub Release ZIP，将其解压为 `Mods/ServerAdmin`；包内包含服务器模组和 Web 管理控制台。本手册只描述当前 `main` 行为，不覆盖历史版本或未启用的功能模块。

## 目的

建立从 Release ZIP 安装、初始管理员配置到日常值班的共同操作模型，并明确软件包、后端和游戏服务器各自负责的边界。

## 开始前

- 将 Release ZIP 作为一个部署单元：解压为 `Mods/ServerAdmin`，让服务器模组和 Web 管理控制台保持配套。
- 准备专用服务器、包内管理控制台的配置 URL 和管理账号，但不要把秘密值写入记录或截图。
- 只有修改后端 API 或构建自定义前端的维护者和部署工程师才使用高级源码流程。

## 产品边界

面向服主的标准软件包由两个必须匹配的部分组成：

- **服务器模组**安装在 `Mods/ServerAdmin` 下。它与游戏进程交互，读取玩家/世界状态，并把配置、审计和历史数据写入后端数据库。
- **Web 管理控制台**包含在同一个 Release ZIP 中。它通过服务器模组的 HTTP API 展示状态和提交管理操作。

Web 管理控制台不能代替游戏服务器或服务器模组；服务器模组不可达时，页面可能仍能打开，但数据和操作不会可靠。功能模块还可能被后端设置、服务器版本或管理员权限禁用。

## 版本适用性

手册以当前 `main` 的菜单和已发布软件包行为为准。服务器模组和 Web 管理控制台必须来自同一个 Release ZIP；不要把不同版本的软件包文件混用。替换 Release 前，按[升级](./upgrade)保留配置和数据。后端 API 变更或自定义前端的源码构建与发布仅适用于维护者，不属于服主的正常部署流程。

## 操作步骤

1. 按[安装](./installation)下载 Release ZIP，将其解压为 `Mods/ServerAdmin` 并验证首次运行。
2. 按[初始管理员配置](./initial-administrator-configuration)完成包内控制台登录、改密、连接、权限、时区和第一次备份测试。初始管理员基线已保存并可审计。
3. 日常值班从[仪表盘](../daily-operations/dashboard)开始，再按玩家、GPS、聊天和日志页面调查。每次调查都以可观察记录或明确的不可用状态结束。
4. 替换 Release ZIP 前，按[升级](./upgrade)保留配置和数据并准备回滚。

## 验证结果

- 浏览器可以登录，仪表盘显示在线/离线状态和最新采样时间。
- 玩家、聊天、审计和游戏事件页面能加载数据，或在确实没有数据时显示空状态。
- 在允许的范围内执行一个无副作用的读取操作，结果出现在控制台或对应日志。
- 第一次备份任务成功，并在备份历史与审计记录中可见。

## 限制与安全说明

::: warning
不要把令牌、密码、真实玩家 ID、真实 IP 或服务器文件路径写入文档或截图。
:::

::: danger
控制台命令、踢出、封禁、传送、发物品和重置资料都可能影响玩家或世界。执行前确认目标、权限、维护窗口和回滚路径。
:::

- 页面显示的是后端采样或持久化记录，不等于游戏进程的每一帧状态。以控制台、审计和游戏事件记录交叉验证。
