# 产品概览与生命周期

> 面向服务器所有者、管理员和轮值运维人员。需要已部署的 7 Days to Die 服务器、可访问的 ServerAdmin 后端和管理账号。本手册只描述当前 `main` 行为，不覆盖历史版本或未启用的功能模块。

## 目的

建立从安装、配置、发布到日常值班的共同操作模型，并明确前端、后端和游戏服务器各自负责的边界。

## 开始前

- 确认游戏服务器、ServerAdmin 后端和前端由同一部署边界负责运维。
- 准备 `<7DTD_SERVER_ROOT>`、`<SERVERADMIN_API_BASE_URL>` 和管理账号，但不要把秘密值写入记录或浏览器变量。
- 后端接口变化时，使用正在运行的后端 Swagger 文档生成前端客户端。

### 产品边界

ServerAdmin 由两个必须匹配的部分组成：

- **后端**是服务器模组和 HTTP API。它与游戏进程交互，读取玩家/世界状态，并把配置、审计和历史数据写入后端数据库。
- **前端**是 Vue 管理控制台。它通过 API 请求展示状态、提交管理操作，并由生成的 OpenAPI 客户端保证请求形状。

前端不能代替游戏服务器或后端；后端不可达时，页面可能仍能打开，但数据和操作不会可靠。功能模块还可能被后端设置、服务器版本或管理员权限禁用。

### 版本适用性

手册以当前 `main` 的菜单和 API 为准。前后端版本必须由同一 Swagger 文档生成客户端；若后端接口变化，先重启后端并确认 Swagger 返回非空 HTTP 200，再重新生成客户端。手册不提供版本切换，也不把开发环境地址当作生产地址。

## 操作步骤

1. 阅读[安装](./installation)，准备服务器根目录、后端发布物和前端构建环境。记录部署边界和 API 地址。
2. 按[初始管理员配置](./initial-administrator-configuration)完成首次登录、改密、连接、权限、时区和第一次备份测试。初始管理员基线已保存并可审计。
3. 发布或升级时使用[发布流程](./publishing)和[升级准备](./upgrade)。前端客户端必须从实际运行的后端生成。
4. 日常值班从[仪表盘](../daily-operations/dashboard)开始，再按玩家、GPS、聊天和日志页面调查。每次调查都以可观察记录或明确的不可用状态结束。

## 验证结果

- 浏览器可以登录，仪表盘显示在线/离线状态和最新采样时间。
- 玩家、聊天、审计和游戏事件页面能加载数据，或在确实没有数据时显示空状态。
- 在允许的范围内执行一个无副作用的读取操作，结果出现在控制台或对应日志。
- 第一次备份任务成功，并在备份历史与审计记录中可见。

## 限制与安全说明

::: warning
不要把令牌、密码、真实玩家 ID、真实 IP 或服务器文件路径写入文档、截图或 `VITE_*` 变量。
:::

::: danger
控制台命令、踢出、封禁、传送、发物品和重置资料都可能影响玩家或世界。执行前确认目标、权限、维护窗口和回滚路径。
:::

- 页面显示的是后端采样或持久化记录，不等于游戏进程的每一帧状态。以控制台、审计和游戏事件记录交叉验证。
