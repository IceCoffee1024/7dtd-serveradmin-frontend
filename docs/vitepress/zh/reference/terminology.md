# 术语

> 统一控制台、后端日志、审计证据和玩家调查中的词汇。编写事故记录或升级信息时，请使用下列含义。

## 运维术语 {#operational-terms}

| 术语 | 定义 | 对管理员的含义 |
| --- | --- | --- |
| **服务器（Server）** | 正在运行的七日杀游戏进程及其世界、玩家、控制台和原生存档。 | 后端响应不能证明游戏进程已经应用了某项修改。 |
| **后端（Backend）** | ServerAdmin 模组/API 进程，负责存储数据、运行任务、提供 Swagger，并与游戏进程通信。 | 诊断前端前先检查后端可达性、日志和功能状态。 |
| **前端（Frontend）** | 在浏览器中运行、调用后端 API 的管理控制台。 | 浏览器时区、语言和缓存客户端代码可能影响显示，但不会改变服务器执行。 |
| **功能模块（Feature module）** | 可独立启用、禁用、初始化并受权限控制的 ServerAdmin 能力。 | 菜单缺失或请求被拒绝可能是有意的模块状态。 |
| **运行时状态（Runtime state）** | 后端或游戏进程持有的内存状态，例如已注册任务、冷却、待执行重启和撤销条目。 | 重启或重载可能重建它，不要把它当作持久历史。 |
| **审计日志（Audit log）** | 在可用时记录管理员或系统动作的来源、目标、原因、结果和时间。 | 用它归因配置或管理变更；导出证据时要脱敏标识。 |
| **游戏事件日志（Game event log）** | 记录受支持的游戏生命周期事件，例如玩家登录、加入、离开、死亡和击杀。 | 用它检查生命周期证据；聊天应查 Chat History，物品获得来源应查 Player Tracking。它与谁改了管理设置是两类证据。 |
| **Cron** | 已注册后端任务使用的五段式计划表达式，例如 `0 5 * * *`。 | 表达式本身没有时区，必须和 `TimeZoneId` 一起解释并用运行历史验证。 |
| **时区（Time zone）** | 解释计划和显示日期所使用的区域，例如 `UTC` 或 `Asia/Shanghai`。 | 留空可能回退到服务器本地时区；浏览器可能使用另一个时区显示。 |
| **保留策略（Retention）** | 按配置周期删除旧历史行、日志、备份或记录的策略。 | 旧行缺失可能是保留策略而不是写入失败，先核对保留周期。 |
| **快照（Snapshot）** | 某个时间点的玩家或系统当前状态副本，例如背包、档案或指标。 | 快照回答“当时有什么”，不一定回答“每件物品最初在哪里生成”。 |
| **获得记录（Acquisition record）** | 将物品获得归因到支持的来源事件，并记录数量、时间和可选坐标的记录。 | 用作调查证据；缺记录不能单独证明违规行为。 |
| **掉落容器（Loot container）** | 由实体生成、可观察为物品来源的掉落容器，例如丧尸包。 | 只有来源事件提供可靠位置时，才会记录坐标。 |
| **恢复（Recovery）** | 从备份、历史、撤销条目或书面回滚流程恢复服务或数据的受控过程。 | 应用恢复前验证文件和目标，并记录操作者和结果。 |

## 证据术语 {#evidence}

- **`NextRunAt`：** API 或界面显示的计算所得下一次运行时间。它只是显示提示，真正决定计划的是保存的 `CronExpression` 和 `TimeZoneId`。
- **`TriggerSource`：** 运行来源，例如 `Cron` 或 `Manual`，用于区分计划执行和管理员触发。
- **运行历史：** 重启、计划任务、备份或事件自动化执行的状态与详情行。被抑制的事件可能有意不创建记录。
- **玩家追踪：** 玩家工作流中的获得记录视图，聚焦支持的物品来源观测，不跟踪之后的每次转移或堆叠合并。
- **来源坐标：** 支持的来源事件提供的位置。游戏或模组未暴露可靠位置时可以为空。

## 使用规则 {#usage-rules}

1. 写明证据来源：审计日志、游戏事件日志、运行历史、快照或线上服务器检查。
2. 对任何计划或时间戳同时记录适用时区。
3. 区分“没有观测到”和“确认不存在”，并明确升级边界。
